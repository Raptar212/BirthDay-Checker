# BirthDay Checker

Напоминалка о днях рождения для Windows (трей) и Android — замена старой Birthday v1.2.2.8
(Delphi, 2012, без исходников; лежит у владельца локально, только чтение). Описание и установка — `README.md`.

## Старая программа
- Записи — в `config.abs` (закрытый формат Absolute Database), напрямую не читаем. Перенос — из
  txt-экспорта (cp1251, `;`): сейчас `Birthday.txt`, записи уже перенесены в рабочий `entries.json`.
- Строка: `MM.DD.YYYY;Имя;Тип;;;;;;<13 флагов True/False>;цвет HEX;флаг;флаг`. Год `0001` —
  неизвестен. 13 флагов — «напомнить за» 1–5 дней, 1–5 недель, 1–3 месяца (по `language\RUS.lng`).
  Последние два флага («разово для года», зодиак) не переносим.
- В данных есть дубли, опечатки, год 2022 вместо года рождения — импорт показывает их списком.
  Конкретные имена в репо не пишем.

## Решения
- **C# / .NET 10 LTS, WPF** (трей — `NotifyIcon` из WinForms), xUnit, гейт `dotnet test`.
  .NET 8 отклонён: поддержка до ноября 2026. SDK закреплён в `global.json`. CI нет.
- Раскладка: `src/BirthdayChecker.Core` (логика без UI, общая для ПК и телефона),
  `src/BirthdayChecker.App` (WPF), `tests/BirthdayChecker.Tests`, `installer/` (Inno Setup),
  `mobile/` (.NET MAUI, только `net10.0-android`).
- В корне один `.slnx`, у мобилки свой `mobile/Mobile.slnx` — иначе `dotnet test` без аргументов
  не работает. Платформенного кода в Core нет; правка Core из мобильной задачи — гейт
  `dotnet test` в корне.
- Только русский язык. Убрано из старой: ICQ, фото, почта, «разово для года», зодиак, скины,
  проверка обновлений, анимация трея.
- Напоминание на ПК — окно программы или balloon значка трея. Настоящие toast отклонены: другая
  целевая платформа и AppUserModelID в ярлыке установщика.
- Тема ПК — встроенная Fluent (`Application.ThemeMode`), светлая и тёмная отличаются только
  цветами. Локальные стили без `BasedOn` сбрасывают тему — не заводим. Все кнопки — один шаблон
  в `App.xaml`, цвета — `TrayApp.ApplyTheme`.
- Фокус и фильтр месяца на ПК — одно состояние (`MainWindow._month`). Месяцы календаря
  одного размера, ширина панели решает только, сколько их в ряду; в узком окне сжимается таблица
  (решение владельца).
- Телефон: свайп список ↔ календарь ловит `MainActivity.DispatchTouchEvent` —
  `SwipeGestureRecognizer` внутри `CollectionView` на Android не срабатывает. Напоминание —
  неточный `AlarmManager` без разрешения на точные, логика — `DailyReminder` в Core, состояние —
  `state.json` (`TrayState`). Первая проверка — в заданное время (9:00), повтор каждые
  1/3/6/12 ч или раз в день до полуночи, пропущенная — сразу; каждый повтор звучит заново поверх
  висящего уведомления. Звук — системный экран канала `reminders`, своего выбора нет.
- «Проверить сейчас» (ПК, виджет — `DailyReminder.CheckNow`): в любое время, всё ближайшее
  (`Upcoming.InReach`), «позже» не учитывает, «не напоминать сегодня» соблюдает.
- Редактор телефона не показывает теги, цвет и свои столбцы, но сохраняет их как были; событие —
  только из списка, новые типы заводятся на ПК.
- Типы событий — `EventCatalog` в `settings.json`, типы только из записей — в конец. Переименование
  типа меняет и записи; удаление типа с записями спрашивает замену, единственный тип с записями
  удалить нельзя.
- Приоритет цвета строки: подсветка ближайших (сегодня / 7 дней), цвет записи, цвет тега. Цветные
  строки в тёмной теме ПК остаются светлыми с чёрным текстом.
- Распространение ПК — установщик per-user в `%LocalAppData%\Programs\BirthDay Checker` без прав
  админа: данные лежат рядом с exe. Пути — `AppLayout` (служебное — в `data\`).

## Ограничения хранилища
- `entries.json` пишут **только главное окно и импорт из трея** (`EntryStorage.Save`), атомарно,
  с копией предыдущей версии. На телефоне — своя копия в `FileSystem.AppDataDirectory`, её пишет
  только `MainPage` (`Commit`, `ChangeEntries`, `ChangeSettings`). Свой `settings.json` телефона
  с ПК не обменивается.
- После неудачного `Load` сохранять нельзя — показать ошибку пользователю.
- Автокопия `Backup\backup-BDC-<дата>.json` — один файл, период в днях (0 — выкл, по умолчанию 7);
  битый или пустой список копию не заменяет.
- Новое поле в записи = поднять `EntryStorage.FormatVersion` (сейчас 3): файл читается строго,
  неизвестное поле — ошибка.
- Импорт CSV/TXT/MD/JSON не меняет файл и пропускает совпадения (тот же Id или имя+событие+дата),
  новые — на выбор галочками (`EntryCsv.Unique`). Импорт txt старой программы заменяет весь
  список — только после подтверждения.

## Версии и git
- ПК — `<Version>` в `Directory.Build.props`, мобилка — `mobile/Directory.Build.props`
  (`versionCode` = major·10000 + minor·100 + patch, теги `mobile-v*`); обе версии — в строке
  версий `README.md`.
  До штатной работы — `0.N.0` по номеру задачи; после 1.0.0 каждое изменение — SemVer
  (функция — minor, исправление — patch), тем же PR.
- Ветка на задачу `BDC-N`, коммит и PR — `BDC-N: <описание>`, в `main` только PR (squash).

## Сборка и ловушки
- ПК: `dotnet test` — гейт, `dotnet run --project src\BirthdayChecker.App` — запуск.
- Установщик: `installer\build.ps1` (Inno Setup 6: `winget install JRSoftware.InnoSetup`) →
  `artifacts\BirthdayChecker-Setup-<версия>.exe` (`artifacts\` не в git).
- Мобилка, один раз: `dotnet workload install maui-android` (от администратора), затем Android SDK
  и свой JDK в `%LocalAppData%\Android` — `dotnet build -t:InstallAndroidDependencies -f net10.0-android
  mobile\BirthdayChecker.Mobile -p:AcceptAndroidSDKLicenses=true`; JDK из winget сборка не
  распознаёт (XA0033).
- Debug-APK из `dotnet build` на устройстве не запускается (Fast Deployment) — проверять Release `dotnet publish`.
- Релиз мобилки: `mobile\build.ps1` подписывает ключом `bdc-release.keystore` + `bdc-release.password`
  из корня основной папки (в `.gitignore`, копия у владельца). Без того же ключа обновление на
  телефон не встанет.
